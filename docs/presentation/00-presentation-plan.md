> **대상**: 개발자 멘토 (기획 보완 과정 + 기술 설계 의사결정)
> **분량**: 15~20분 / 슬라이드 약 18~19장
> **구성 전략**: **AS-IS → 멘토링 피드백 → TO-BE(보완)** 서사. 리서치(데스크 리서치) 6개 문서를 기획 보완의 핵심으로, 기술 설계는 "왜 이렇게 설계했나"의 의사결정 Deep Dive로 배치.
> **산출물 경로**: 본 기획 확정 → Canva 슬라이드 제작
> **핵심 근거**: `docs/mentoring/2026-06-02-feedback.md`, `docs/research/{01,02,03,04,10,11}`, `docs/design/*`, 설문 `장독대_설문조사.csv` (**N=40**, 2026-06-04~08)

## 발표 흐름 한눈에

```
[Part 0] 오프닝
[Part 1] AS-IS — 멘토링 이전 초기 기획의 한계
[Part 2] 멘토링 피드백 (기획축 + 기술축)
[Part 3] TO-BE ① 기획 보완 — 데스크 리서치   ← research 01·02·03·10·04·11 (6장)
[Part 4] TO-BE ② 기술 보완 — 설계 의사결정     ← 핵심 결정 4개 Deep Dive
[Part 5] AS-IS → TO-BE 종합 & 마무리
```

발표를 관통하는 한 문장:
> **"멘토에게 받은 피드백을, 데스크 리서치와 아키텍처 설계로 어떻게 메웠는가."**

각 슬라이드는 **제목 / 핵심 메시지 / 들어갈 자료 / 근거 출처**로 정리. 보완 슬라이드에는 **`← 멘토 피드백 X 반영`** 태그를 달아 AS-IS→TO-BE 연결을 명시. 기술 Deep Dive는 **[문제] → [선택] → [포기한 것]** 구조.

## Part 2. 멘토링 피드백 (1장)

### S4. 멘토링 피드백 핵심 (2026-06-02)
- **핵심 메시지**: 피드백은 "근거를 만들어라"로 수렴 — 기획은 데스크 리서치로, 기술은 컴포넌트 경계와 데이터 전략으로
- **들어갈 자료** (두 컬럼):

  - **기술축**: ① 컴포넌트 한계 명확화(작업 성격별 도구 배치) ② RAG 엣지케이스 처리 주체 ③ 벡터DB 적재 시 카테고리화(1차 필터) ④ 원문 LLM 요약 → 임베딩 ⑤ 호출 단위 단일 책임
- **근거**: `mentoring/2026-06-02-feedback.md` §1, §2

## Part 3. TO-BE ① 기획 보완 — 데스크 리서치 (본편 핵심, 6장)

> 멘토 "AI 설계가 아니라 데스크 리서치부터"를 그대로 실행. 순서: 경쟁(어디) → 타깃(누구) → 여정(어떻게) → 통증(무엇) → 검증(맞나) → 가치(왜).

### S5. 벤치마킹 — 빈틈을 찾다 `← 멘토 피드백: 벤치마킹 3~4개`
- **핵심 메시지**: 경쟁사가 못 채운 자리에서 우리 포지션이 나온다
- **들어갈 자료**:
  - 4개 비교: 토스증권(거래) · 어피티(종합 경제) · 핀트(일임) · 로빈후드(시장 창출)
  - 로빈후드 반면교사: 진입장벽만 낮추면 준비 안 된 유입 → 손실(학습·보호 레이어가 차별점)
  - 빈틈 5가지: 개인화 큐레이션 · 주식 특화 심화 · 단계적 커리큘럼 · 정확한 쉬움 · 학습 자산화
  - 한 줄 포지셔닝: "핀트가 떠먹여준다면, 장독대는 읽는 법을 가르쳐 스스로 판단하게"
- **근거**: `research/01-benchmarking.md`

### S6. 페르소나 — "주린이"를 측정 가능하게 `← 멘토 피드백: 타깃 좁혀라 / 독해력 진입장벽`
- **핵심 메시지**: 모호한 "경력 1~2년" 대신 4축으로 측정 가능하게 정의
- **들어갈 자료**:
  - 타깃 4축: 투자 경험(1~2년) · 경제용어 이해 · **독해 수준(공시 못 읽음)** · 연령(2030)
  - Primary: 김주린(28, 직장 3년차, 독해+손실 공포) / Secondary: 이코린(24, 취준생)
  - 확장: 정워킹·박관망·최늦깎이·한회복 (TAM 확장 깔때기)
- **근거**: `research/02-persona.md`

### S7. 유저 저니맵 — 이탈 지점을 찾다 `← 멘토 피드백: 저니맵 산출물`
- **핵심 메시지**: 페르소나별 여정의 최저점이 곧 P0 기능 우선순위
- **들어갈 자료**:
  - 김주린 저니의 최저점: ① 신뢰 의심(리딩방 피로) ③ 가치 체감
  - P0 기능: 내 종목·수준 맞춤 **쉬운 해설** + **출처·검증 시그널**
  - P1: 초간단 온보딩 · 개인화 아침 브리핑 · 약점 기반 커리큘럼
- **근거**: `research/03-user-journey.md`

### S8. Pain Point — 표면과 근본을 분리 `← 멘토 피드백: Pain Point가 핵심`
- **핵심 메시지**: 사용자가 호소하는 Pain과 진짜 원인은 다르다 → 메시지 전략이 갈린다
- **들어갈 자료**:
  - 6대 Pain 지도(기능·감정·시간)
  - **표면 호소**: 손실 공포 35% · 시작점 모름 30% (마케팅·온보딩 후킹용)
  - **근본 원인**: 독해 불가 (직접 호소는 2.5% 최하위지만 제품 핵심 가치)
  - 악순환 고리: 독해 불가 → 시작점 혼란 → 검증 안 된 정보 → 손실 → 불안
- **근거**: `research/10-pain-points.md`, 설문 E1

### S9. 설문 검증 — 가설을 실측으로 `← 멘토 피드백: 간이 설문으로 측정` **(N=40)**
- **핵심 메시지**: 페르소나·Pain 가설을 N=40 설문으로 보정 — 핵심 가설 모두 확인
- **들어갈 자료** (N=40 최신 수치):
  - **독해 절벽 확인**: 헤드라인 77.5% → 본문 65% → **리포트 42.5% → 공시 20% → 재무제표 20%**
  - **심화 용어가 장벽**: ETF 87.5%·배당 95%·손절 92.5% vs **컨센서스 52.5%**
  - **포지셔닝 강확**: "독해 대행" 선호 **60%** (알림 15% · 일임 12.5% · 강의 5%)
  - **주린이 역설**: 77.5%가 "나는 주린이" · 졸업 기준 "스스로 종목 분석" 67.5%
  - 지불의사: 무료 67.5% / ~3,000원 25% / ~6,900원 7.5% (편의표본·탐색적 명시)
- **근거**: `research/04-survey.md` + `장독대_설문조사.csv` (N=40)

### S10. 왜 장독대인가 — AI 대체 가치 `← 멘토 피드백: AI가 사람을 얼마나 대체하나`
- **핵심 메시지**: 1:1 독해는 사람으로는 불가능, AI라서 비로소 열린 시장
- **들어갈 자료**:
  - 내러티브 아크: 진입(1,410만) → 못 읽음 → 검증 안 된 지출(리딩방 1.3조원) → 1:1 독해는 인건비상 불가 → AI가 1:다 비용으로
  - **정량화**: 공급 인건비 월 50만원/인 → AI 월 1~2천원(**99.6%↓**) / 사용자 시간가치 월 8만원 절감(ROI 약 20배)
  - 멘토 벤치마크 연결: 신한 인공인간·보험사 해피콜 = "시장 독해 해피콜"
- **근거**: `research/11-why-jangdokdae.md`

## Part 4. TO-BE ② 기술 보완 — 설계 의사결정 Deep Dive (6장)

> "왜 이렇게 설계했고 무엇을 포기했나." 각 결정은 **[문제] → [선택] → [포기한 것]** 구조. 멘토 기술 피드백과 연결.

### S11. 전체 아키텍처 전경
- **핵심 메시지**: 수집 → 전처리 → 임베딩·클러스터링 → 분석 → 번역, 5단계 한 흐름
- **들어갈 자료**:
  - 파이프라인 흐름도 1장 (Canva 도식)
  - 스택·레이어: FastAPI 계층형(API→Service→DB/LLM) · pgvector(Neon) · Vertex AI Gemini · LangChain/LangGraph · Airflow · 프롬프트 `prompts/*.yaml` 외부화
- **근거**: `architecture.md`, `design/01-pipeline-orchestration-design.md`

### S12. 결정 ① 왜 2계층 오케스트레이션인가 `← 멘토 피드백: 컴포넌트 한계 명확화`
- **핵심 메시지**: 정형 단계와 추론 단계는 오케스트레이션 도구가 달라야 한다
- **들어갈 자료**:
  - 분기 기준 한 줄: **"LLM이 다음 흐름을 판단하는가?"** → Yes면 LangGraph(L2), No면 Airflow(L1)
  - L1: 수집·전처리·임베딩(스케줄·재시도·관측성) / L2: 분석(추론 기반 동적 흐름)
  - 단계 간 DB 핸드오프(상태 계약: `is_filtered`/`embedding=NULL`/`is_analyzed`)
  - **포기한 것**: MasterOrchestrator 단일 제어 → 제거, 멱등성(미처리 레코드만 재개)으로 대체
- **근거**: `design/00-workflow-airflow.md`, `design/01-pipeline-orchestration-design.md`

### S13. 결정 ② 왜 메타데이터만 수집하고 적재/on-demand를 나눴나 `← 멘토 피드백: 카테고리화·원문 축약`
- **핵심 메시지**: 저작권·비용 리스크를 수집 단계에서 원천 차단하고, 적재 전에 거른다
- **들어갈 자료**:
  - 뉴스: 고정 RSS 16개 + **메타데이터만 저장**(제목·URL·출처·발행일), 본문은 분석 시점 실시간 fetch 후 폐기
  - 기업: 적재(공시 메타·재무제표·사업보고서 청크·거시지표) vs on-demand(주가·환율) 분리, DART 구조화 재무 API 직접 사용
  - 카테고리화(1차 필터) + 원문 축약 → 임베딩 (멘토 반영)
  - **포기한 것**: 본문 상시 저장 → 저작권 리스크로 포기
- **근거**: `design/02·03·04`, `mentoring §1-4·1-5`

### S14. 결정 ③ 왜 HDBSCAN + 복합 중요도 스코어인가
- **핵심 메시지**: 뉴스량을 모르는 상황엔 클러스터 수를 안 정해도 되는 HDBSCAN
- **들어갈 자료**:
  - HDBSCAN: 클러스터 수 미지정 · 노이즈 자동 분리 · **singleton 이슈 보존**(`min_cluster_size=2`, `min_samples=1`)
  - 임계값: 중복 제거 cosine ≥0.95, 클러스터링 cosine ≥0.80
  - 이슈 선정: `importance = 0.4·volume + 0.3·velocity + 0.15·sentiment + 0.15·entity` → 상위 10개만 분석 인계(LLM 비용 통제)
  - 임베딩 모델 후보(미확정): gemini-embedding-001 vs KURE-v1 vs ko-sroberta
- **근거**: `design/05-embedding-clustering-design.md`

### S15. 결정 ④ 분석 에이전트 — 단일에서 멀티로 "승격" 설계
- **핵심 메시지**: 분류(L1/L2/L3)가 본문 구조를 결정, 처음엔 단일·필요 시 멀티 승격
- **들어갈 자료**:
  - 3계층 분류: L1(5) / L2(6) / L3(태그) → 4-head 본문(무슨 일·왜/뭐가 다른가·★오해 방지·뭘 보면 될까)
  - 단일: classify → generate_content → build_connection → generate_quiz → publish
  - 승격: 슈퍼바이저-워커(이슈요약·용어해설·종목연결·배경맥락·품질검증)
  - **트레이드오프**: 초기 단순성 우선, 멀티 승격 시점은 품질·지연 보고 후 결정(미결)
- **근거**: `design/06-news-analysis-design.md`

### S16. 결과물 — 주린이 번역 콘텐츠
- **핵심 메시지**: 파이프라인의 출력은 "읽히는" 한 장의 Issue Docent
- **들어갈 자료** (가능하면 목업 1장):
  - 용어 풀이(클릭형) · 전문가의 시각(근거 강조) · 본문 근거 하이라이트 · 이해도 퀴즈 3문항 · 다음 이슈 추천 4개(관련 2 + 관심 1 + 랜덤 1)
  - 추천 로직: pgvector 코사인 유사도 + 섹터/기업 겹침 + 다양성
- **근거**: `design/07-jangdokdae-translation-design.md`

## Part 5. AS-IS → TO-BE 종합 & 마무리 (2장)

### S17. AS-IS → TO-BE 한 장 요약
- **핵심 메시지**: 멘토 피드백 하나하나가 산출물로 닫혔다
- **들어갈 자료** (Before/After 매핑 표):

  | 축 | AS-IS (멘토링 전) | TO-BE (보완) |
  |---|---|---|
